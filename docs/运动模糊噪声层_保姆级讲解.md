# 运动模糊噪声层：保姆级讲解

> 面向：觉得旧文档公式看不懂、但想真正搞懂我们在干什么的人。  
> 对应代码：`AS_VALs/python_motion_blur/motion_blur.py`、`Noise_Layer.py` 里的 `ScreenShootingMB`。  
> 更偏公式/参数区间的旧文档仍在：`AS_VALs/非线性运动模糊方案_参数与实现.md`、`PIMoG_非线性运动模糊改进汇报.md`。

---

## 0. 先用一句话记住

**训练时假装「手抖着拍屏幕」：在快门打开的那一小段时间里，相机又平移又旋转，传感器把沿途看到的画面叠在一起，就糊了。**

我们把这个过程做成**可微**的（能反传梯度），塞进 PIMoG 原来的拍屏噪声前面，得到新噪声层：

**`ScreenShootingMB` = 非线性运动模糊 → 再接原来的透视 / 光照 / 摩尔纹 / 高斯噪声。**

---

## 1. 为什么要加这一层？

原版 PIMoG 的 `ScreenShooting` 已经模拟了：

- 透视（斜着拍）
- 光照不均
- 摩尔纹（屏幕像素网格干涉）
- 一点高斯噪声

但**没有**模拟最常见的一种实拍伤害：**手持曝光期间的抖动拖影**。

你实拍表里也能看到：一上「轻度 / 中度抖动」，Acc 掉得比静止猛得多。  
所以训练时若从不见过「糊」，模型就容易虚高；加上运动模糊再训，才会更扛实拍。

---

## 2. 生活类比：慢门拍灯

晚上用手机拍路灯，手一抖，灯会拖出一条光痕。

| 现实 | 我们的模型 |
|:---|:---|
| 快门打开一段时间 | 时间 $t$ 从 0 走到 1 |
| 手在抖 → 相机相对画面在动 | 「取景窗」的中心和角度在变 |
| 感光元件把这段时间看到的光累加 | 对多帧画面做**平均** |
| 灯拖出一条线 | 每个像素沿着自己的路径「扫」过源图 |

注意：糊不是「整张图同一个方向抹一下」那么简单——有旋转时，**左上角和右下角扫过的路径不一样**。这就叫**空变（spatially-variant）**。

---

## 3. 三个核心物件（先别看公式）

### 3.1 取景窗（view）

想象源图是一整张大照片。我们不看整张，而是拿出一个正方形小窗口去「取景」。

训练里图通常是 $128\times128$，窗口也取满幅，所以窗口几乎就是整图；演示脚本里窗口可以更小。

窗口上有自己的本地坐标 $(u,v)$：

- 中心是 $(0,0)$
- 左边 $u$ 为负，右边为正；上边 $v$ 为负，下边为正（和代码网格一致即可，先有个方向感）

### 3.2 位姿 $g$（pose）

描述「窗口此刻贴在源图的哪里、转了多少」：

$$
g = (c_x,\ c_y,\ \theta)
$$

| 符号 | 人话 |
|:---|:---|
| $c_x, c_y$ | 窗口中心落在源图的哪个像素位置 |
| $\theta$ | 窗口相对水平线转了多少弧度（代码里起点常固定 $\theta_0=0$） |

一次曝光要两个位姿：

- **起点** $g_0$：快门刚按下
- **终点** $g_1$：快门即将关闭

中间所有时刻的位姿，都在 $g_0$ 和 $g_1$ 之间「插值」出来。

### 3.3 轨迹（每个像素自己的小路）

对输出图上某一个固定格点（本地坐标固定的那个 $(u,v)$）：

- $t=0$ 时，它在源图上对准某个 $(x_0,y_0)$
- $t=1$ 时，对准另一个 $(x_1,y_1)$
- 中间每个时刻对准一条曲线上的点

**输出像素的颜色 = 沿着这条小路，把源图颜色按时间平均。**

有平移时，大家路径大致平行；再加旋转，角落路径会弯、会更长——所以叫**非线性 / 空变**运动模糊。

---

## 4. 「匀加速」到底在说什么？（最容易懵的地方）

### 4.1 不要和「中间糊、两头清」搞混

以前有一种写法：时间上用**高斯权重**，中间时刻权重大。  
那只是说「中间曝光贡献大」，**不等于**相机在中间走得慢。

我们现在的约定更物理：

1. **真实时间 $t$** 均匀采样：$0,\ 0.25,\ 0.5,\ 0.75,\ 1$（举例）  
2. **每一帧权重一样**：都是 $1/K$（快门均匀打开）  
3. **几何进度**用幂函数拉扯：$\lambda(t)=t^{p}$

默认 $p=2$（代码参数 `path_power=2`）：

| $t$（时间走了几成） | $\lambda=t^2$（几何走了几成） | 直觉 |
|:---:|:---:|:---|
| 0.0 | 0.00 | 还在起点 |
| 0.5 | 0.25 | 时间过半，位置才走了 1/4 |
| 1.0 | 1.00 | 到达终点 |

也就是：**起步慢、越往后位移越快**——类似从静止开始的匀加速（速度大致随时间变大，位移大致随时间平方）。

若设 `path_power=1`，则 $\lambda=t$，姿态空间里接近**匀速**。

### 4.2 用数字看插值（只要会加减乘）

假设中心只在水平方向从 $c_{x0}=10$ 挪到 $c_{x1}=20$（其它不动）：

$$
c_x(t) = (1-\lambda)\,c_{x0} + \lambda\,c_{x1}
$$

当 $p=2,\ t=0.5,\ \lambda=0.25$：

$$
c_x = 0.75\times 10 + 0.25\times 20 = 12.5
$$

时间过半，中心才从 10 挪到 12.5，不是 15。这就是「前半段挪得少、后半段挪得多」。

代码里就是：

```python
lam = t ** path_power
cx = (1 - lam) * cx0 + lam * cx1
# cy、theta 同理
```

## 5. 曝光积分：把多帧叠成一张糊图

伪代码（和 `nonlinear_motion_blur` 一致）：

```text
准备一张全 0 的累加图 acc
把时间 0→1 均匀切成 K 份（K = n_samples，训练默认常为 8）

对每一个时间点 t_k：
    算 λ = t_k ^ path_power
    用 λ 插值出当前位姿 (cx, cy, θ)
    按位姿，从源图双线性采样出一帧 frame
    acc += (1/K) * frame

输出 acc  ← 这就是运动模糊后的取景结果
```

### 5.1 为什么叫「可微」？

采样用的是 PyTorch 的 `grid_sample`（双线性插值）。  
糊图对「嵌入图像素」可求导，水印网络才能通过噪声层反传，学会「怎么嵌才能扛糊」。

### 5.2 $K$ 越大怎样？

- $K$ 大：拖影更平滑，更慢  
- $K$ 小：更快，拖影略「颗粒」  
训练默认 `n_samples=8`，是速度和观感的折中。

## 6. 「空变」一张图说明白

假设只有平移、没有旋转：每个像素的位移向量差不多一样 → 接近普通方向模糊。

一旦有旋转：

```text
        终点相对起点转了一点
   ┌────────────┐
   │ ↘    ↓    ↙ │   箭头 = 该像素在曝光期间扫过的方向
   │ →    ·    ← │   中心附近位移短，四角更长、方向不同
   │ ↗    ↑    ↖ │
   └────────────┘
```

所以：

- **不是**卷积一个固定的小核扫全图（那种叫空间不变 PSF）  
- **是**每个输出像素自己查一条路径再平均

这也是名字里 **nonlinear / spatially-variant motion blur** 的来源。

---

## 7. 起点终点怎么随机出来？

函数：`sample_pose_pair(...)`

白话流程：

1. 随机一个合法的起点中心 $g_0$（窗口不能一开始就超出图外）  
2. 在限制范围内随机终点：  
   - 平移不超过 `max_trans`（训练里常按边长比例，如约 $0.06\times128$）  
   - 旋转不超过 `max_rot_deg`（训练默认约 12°）  
3. 检查从起点到终点整条路径上，窗口四角是否一直落在图内  
4. 不合法就重抽，直到成功（或放弃后走兜底）

目的：避免糊的过程大量采到图外黑边，训练信号更干净。

## 8. `ScreenShootingMB` 整条流水线

训练时一张嵌入图走进噪声层，顺序是：

```text
嵌入图 (约 [-1,1])
    │
    ▼
① 非线性运动模糊     ← 我们新增的
    │
    ▼
② 透视扭曲           ← 原 PIMoG
    │
    ▼
③ 光照 + 摩尔纹      ← 原 PIMoG，但摩尔纹权重会随抖动变
    │
    ▼
④ 高斯噪声           ← 原 PIMoG
    │
    ▼
送进 Decoder 提水印
```

对应类：`Noise_Layer.ScreenShootingMB`。  
命令行开关：`--distortion ScreenShootingMB`。

## 9. 「抖动强 → 摩尔纹弱」是什么意思？

实拍时：手抖很厉害，高频的屏幕网格干涉（摩尔纹）往往也被抹掉；  
手很稳时，摩尔纹反而更明显。

我们用一个简单的反比（不是精确物理仿真，是训练用的合理耦合）：

1. 算模糊强度 $s$：所有像素「起点→终点」位移长度的平均值  
2. $\beta = \mathrm{clip}(s / \texttt{blur\_ref},\ 0,\ 1)$  
3. $\alpha_{\mathrm{moire}} = \texttt{moire\_max}\times(1-\beta)$  
4. 光照权重相应抬一点，使两者大致此消彼长  

| 情况 | $s$ | $\beta$ | 摩尔纹权重 |
|:---|:---|:---|:---|
| 几乎不抖 | 很小 | → 0 | 接近最大（如 0.15） |
| 抖得很凶 | ≥ blur_ref | → 1 | → 0（几乎不加摩尔纹） |

函数：`blur_moire_weights`；强度：`mean_trajectory_length`。

## 10. 和「整图高斯模糊」差在哪？

| | 高斯模糊（旧式「其它攻击」） | 我们的运动模糊 |
|:---|:---|:---|
| 做法 | 一个模糊核卷积整图 | 沿刚体轨迹时间积分 |
| 各像素 | 同一套核 | 路径可以不同 |
| 有无旋转 | 核仍是各向同性/固定 | 旋转会造弯曲拖影 |
| 物理含义 | 失焦/柔化的粗近似 | 手持曝光拖影的粗近似 |

你们早期讨论过：不要把「高斯时间权重」理解成匀加速；**匀加速在路径 $\lambda(t)=t^2$ 上，权重用均匀 $1/K$。**

## 12. 常用参数（白话版）

| 参数 | 默认直觉 | 调大之后 |
|:---|:---|:---|
| `path_power` | 2 = 匀加速感 | 更大则「更晚才猛冲」；1 = 匀速感 |
| `n_samples` | 8（训练） | 更平滑、更慢 |
| `max_trans_ratio` | 约 0.06×边长 | 平移拖影更长 |
| `max_rot_deg` | 约 12° | 旋转拖影更明显 |
| `moire_max` | 0.15 | 静止时摩尔纹上限 |
| `blur_ref` | 随分辨率自适应 | 多大的 $s$ 算「抖满」 |

## 13. 常见误区 Checklist

1. **「λ 是时间」** → 不是。$t$ 才是时间；$\lambda=t^p$ 是几何进度。  
2. **「权重高斯 = 中间走得慢」** → 我们已不用高斯曝光核；权重均匀。  
3. **「和距离无关」** → 噪声层在像素域抖动；实拍距离/焦距通过成像尺度影响糊的观感，那是实验设计问题，不是这一层直接输入米数。  
4. **「ScreenShootingMB 只有模糊」** → 模糊只是第一段，后面仍有透视等。  
5. **「公式里的 1-based 坐标」** → 为了和 MATLAB demo 对齐；PyTorch 采样前会换成 $[-1,1]$ 网格，你不必手算。

## 14. 如果你只想向别人解释 30 秒

> 我们在 PIMoG 拍屏噪声前加了一层可微运动模糊：随机一个取景窗的起止位姿（平移+旋转），按匀加速进度插值，在快门时间内等权叠加多帧采样，得到空变拖影；抖动越强，后面摩尔纹越弱。用这个噪声再训练，模型更扛手持屏摄。
